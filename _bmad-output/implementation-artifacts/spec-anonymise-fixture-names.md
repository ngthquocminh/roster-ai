## Intent

**Problem:** Both governed fixtures (`data/sample_tiny_input.json`, `data/sample_tiny_input_more_tm.json`) carry real team-member names, employee numbers (SAPID), enterprise-agreement names, and site-specific task/area names from a real business, and those names leak into tests, agent prompt examples, comments, and BMAD artifacts.

**Approach:** Replace them with synthetic values produced by a committed, deterministic rule script (tasks named by a structural rule; areas `Chiller` / `Freezer` / `Main`), regenerate the contract projections, then replace every remaining mention across the tracked tree.

## Boundaries & Constraints

**Always:** The committed script and every committed file contain zero real names — the old→new lookup used for the reference sweep lives only in the session scratchpad. Every GUID, number, time, rate, volume and relationship stays byte-identical; only name-like strings change. Fixture bytes keep their format (`indent=2`, LF, no trailing newline). The rename preserves every token-resolution property tests rely on (see Design Notes). Contract projections are regenerated by `export_contract_fixture.py`, never hand-edited.

**Ask First:** Any test failing for a reason other than a changed name literal or contract digest. Any change to an `evidence/**` file.

**Never:** Edit evidence files (decision A: digest mismatch is drift, per EVIDENCE-CONVENTION.md). Bump fixture version `v1`. Rewrite git history. Touch `Test Member NN` rows (already synthetic) or Function names (generic). Stage the unrelated `RunsTable.tsx` change.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Run rule script | original fixtures | names/SAPID/EBA/area/task rewritten; all other bytes unchanged | abort without writing if load→dump does not round-trip the original bytes |
| Re-run script | already-anonymised fixtures | byte-identical output (idempotent) | N/A |
| Duplicate person | one ContactID on two Team Member rows | both rows get the same synthetic name and SAPID | N/A |
| Unknown area/function | a Task whose area/function is not in the rule table | script fails loudly | raise, write nothing |

## Design Notes

**Task naming rule:** `{Area} {Function} | {Activity} {Code}`
- Area: `Chiller`, `Freezer`, `Main` (area row renamed; Code also `Main`).
- Function label from Function row: Receiving→`Receive`, Putaways→`Putaway`, Despatch→`Despatch`, Pick→`Pick`.
- Activity from function: Receive→`Unloader`, Putaway→`Forklift`, Despatch→`Loader`, Pick→`Order Picker`.
- Code: area initial + 2-digit ordinal within that area in fixture Task order.

Result: `Chiller Putaway | Forklift C01`, `Chiller Pick | Order Picker C02`, `Main Receive | Unloader M01`, `Freezer Pick | Order Picker F01`, `Main Pick | Order Picker M02`, `Main Despatch | Loader M03`. The pipe and trailing code keep the shape the grounding-gate and prompt examples exercise ("dropping a trailing code token").

**Members:** a fixed list of 10 synthetic names assigned by first-seen ContactID order among non-`Test Member` rows: Mika Tane, Arjun Patel, Lena Ortiz, Owen Hale, Priya Nair, Nina Brooks, Theo Marsh-Walker, Felix Van Dijk, Hana Sato, Ravi Kumar. Constraints: unique first names; no name is a case-insensitive substring of another; no first name is hex-only (resolution also substring-matches GUID `contact_id`). The hyphenated and multi-word surnames keep those edge cases. SAPID → `998000NN` in the same order. EBA names → `Agency Agreement` / `Site Agreement` (Code likewise).

**Known consequence:** Gate A reports "drift" on the 5 evidence files pinning old contract digests (non-blocking by design). A local Postgres that already imported `v1` rejects the new checksum — reset the local DB volume.
