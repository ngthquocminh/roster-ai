## 1. Epic review

### Delivery outcome

Epic 3 delivered the complete governed repair path: reversible drafts, immutable run snapshots, deterministic candidates, leased and fenced execution, safe cancellation, literal run state and replay, explicit optimization, run monitoring, candidate/baseline comparison, model-outage continuity, and proof at correctness, recovery, and browser layers.

All 12 stories are complete. Final recorded evidence includes:

- Backend: 1,290 passed, 1 skipped, 7 deselected.
- PostgreSQL: 95 passed.
- Frontend: 529 tests passed.
- Browser: 52/52 across Chromium and Edge.
- Gate A: passed with ten invariants and no blockers.

Epic 3 is accepted as a verified local/portfolio capability. It is not a deployed production service; production worker composition and hosting remain explicitly owned by Epics 5 and 6.

### What went well

1. **Safe LLM-system design became the epic's main value.** The model is not a single point of failure: the planner retains deterministic scheduling capability during model outage, and durable, immutable records permit safe correction instead of in-place rewriting.
2. **Authority boundaries held.** Model intent, application governance, and CP-SAT schedule construction remained separate across the repair journey.
3. **Real-boundary tests found meaningful defects.** Story 3.8's solve-to-comparison integration proof exposed demand-record identifier mismatch and floating-point aggregation drift that isolated tests did not reveal.
4. **Proof matured from components to journey.** Stories 3.10–3.12 proved deterministic correctness, worker-kill recovery, idempotency, browser routing, and accessibility; browser testing found real contrast and focus defects.
5. **Earlier retrospective commitments improved the process.** The domain model was documented, citable facts appeared in every Epic 3 story, CI was established, and Gate A became consecutively rerunnable.

### Challenges and lessons

- Review resolved 172 patch findings and 10 decision findings; 47 deferrals remain recorded. This is a systems signal, not an individual-performance finding.
- Detailed FRs, ADs, and tasks reduce ambiguity but cannot replace adversarial execution evidence. Some issues appear only where real persistence, concurrency, solver, API, and browser paths meet.
- The recurring failure mode is a guard that passes without proving a meaningful failure. A passing assertion is insufficient unless it can be made to fail by an intentional relevant mutation.
- A mechanism can be proven without being production-composed. The worker loop and recovery mechanism are proven; its non-test runtime factory and deployment composition are not yet supplied.
- Planning records require active reconciliation. The Gate A rerunnable fix is in code and Story 3.1, but an older deferred-work entry still says the opposite.

### Key insight

The product differentiator is not merely Schedule Repair UI. It is a governed planning system in which stochastic assistance can fail without taking down deterministic planning, evidence, version history, or recovery.

## 3. Epic 4 preparation and planning update

Epic 4 remains the correct next direction, but it requires a planning update before Story 4.1 is created. This is a refinement based on Epic 3 evidence, not a change in product direction.

### Required design decisions

1. **Baseline semantics:** no baseline is an explicit valid state. First approval establishes the operational baseline; later approval replaces an exact named baseline.
2. **Audit identity:** retain `actor_id` for authenticated human commands, while distinguishing initiating planner, deciding planner, and automated worker/job-attempt execution.
3. **Persisted approval workflow:** persist the exact binding and `approval_required` pause; reconnect/replay must restore it; approve, reject, expiry, and staleness must have literal, idempotent outcomes.
4. **Approval-driven cancellation:** rejection or expiry produces `agent_cancelled` with explicit reasons such as `approval_rejected` or `approval_expired`. This does not add general user-initiated AgentRun cancellation.
