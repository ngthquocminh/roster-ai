## Deferred from: code review of story-1-3-choose-an-immutable-fixture (2026-07-27) — backend chunk

- **Fixture version ordering is a lexical sort on a free-form `String(100)` column** [backend/adapters/postgres/scenario_catalogue.py:46-50,88-91]. `ORDER BY version` places `v10` before `v2`, and `ORDER BY version DESC ... LIMIT 1` resolves `v9` as "latest" over `v10` — publishing the wrong `fixture_version` and `checksum_digest` from a provenance endpoint. Reviewed and **accepted as specified**: Task 1 prescribed exactly this ordering, AC #1 requires only *determinism* (which a lexical sort satisfies), and exactly one version per fixture exists today. **Action for whichever story first introduces multi-version fixtures:** switch to a zero-padded or parsed version ordering, or constrain the column format so lexical order is semantic order (the latter needs a migration, which Story 1.3 was forbidden to add).
- No generic `Exception` handler is registered, so any database failure on a `/api/v1` path escapes the RFC 7807 problem-details contract [backend/api/main.py:50-94]. Only `RequestValidationError` and `HTTPException` are handled; an `OperationalError` raised from `get_site_context` reaches Starlette's default `text/plain` 500 even though the routes advertise `ProblemDetailsV1`. Pre-existing since `/api/v1` was introduced in Story 1.2, and an app-wide concern better fixed in one pass than per-router.
- `TestClient(app)`'s lifespan calls `get_settings()` directly instead of consulting `app.dependency_overrides` [backend/api/main.py:42]. Test fixtures that override `db_path` and `maintenance_flag_path` are therefore inert at startup: `db.init_db` initializes the developer's real SQLite file and `_gate_a_flag_is_set()` reads the ambient flag path. The overrides read as isolation but provide none.
- `imported_at` is never normalized to UTC before serialization [backend/adapters/postgres/scenario_catalogue.py:42]. `TIMESTAMPTZ` comes back in the Postgres session's timezone, so the published contract can shift from `2026-07-24T00:00:00Z` to `2026-07-24T02:00:00+02:00` on server configuration alone. The contract test cannot catch it — it feeds a hardcoded UTC value through a stub reader.
- The catalogue ordering assertion compares Postgres collation order against Python codepoint order [backend/tests/test_postgres_integration.py:198-208]. It agrees today only because the seeded fixture ids differ on their first letter; ids differing in punctuation or case would diverge, and the SQL pins no collation.
- Two undiscussed response shapes on `GET /api/v1/scenarios/{scenario_id}` [backend/adapters/postgres/scenario_catalogue.py:19-26]: the inner join makes a `scenario` row with zero `scenario_version` rows return 404 despite existing and being visible to the caller's site, and a malformed non-UUID id returns 422 `invalid_request` — a third class alongside the specified 401/404. Neither discloses site membership, so AD-3 non-disclosure still holds.
