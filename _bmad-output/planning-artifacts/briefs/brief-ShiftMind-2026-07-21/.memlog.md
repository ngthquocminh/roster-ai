- (decision) The MVP serves one authenticated planner in one DC site, while ownership and data boundaries remain tenant-ready for future organizations, sites, users, and roles.
- (decision) Full SaaS administration, billing, self-service registration, and production-scale multi-tenancy are excluded from the MVP and documented as evolution paths.
- (event) Brownfield baseline already ships the CP-SAT engine, FastAPI API, provider-neutral LLM adapters, five validated scheduling overrides, grounded insights, SQLite persistence, and React UI.
- (decision) The product centerpiece is a conversational DC scheduling agent that investigates data, proposes actions, invokes deterministic scheduling tools, and explains outcomes.
- (decision) Portfolio strength comes from a narrow end-to-end agent workflow implemented robustly, with visible system design, safety controls, auditability, and asynchronous execution.
- (decision) The LLM orchestrates typed tools but does not generate schedules; OR-Tools CP-SAT remains the source of scheduling decisions.
- (decision) Immediate purpose is a robust portfolio MVP for an AI Engineer CV and interview demo; real SaaS commercialization is a later phase.
- (assumption) The portfolio MVP adds a separate conversational AgentModel contract and application-owned orchestrator while preserving the shipped task-specific LLMProvider operations.
- (assumption) Read-only agent tools may execute automatically, while schedule-affecting mutations require preview and explicit planner confirmation.
- (assumption) SQLite and the local single-worker executor remain acceptable for the portfolio MVP if run inputs are snapshotted and the production migration path is documented.
- (decision) Commercial novelty is not an MVP claim: current enterprise products already combine AI assistance and workforce optimization, so ShiftMind differentiates through transparent DC-specific architecture, safety controls, grounded comparisons, and evaluation evidence.
