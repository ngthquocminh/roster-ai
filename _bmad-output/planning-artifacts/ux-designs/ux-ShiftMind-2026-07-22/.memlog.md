- (event) Create intent confirmed in autonomous/headless fast-path mode from the updated ShiftMind PRD package; creative tools and reviewer gate are skipped by headless default.
- (decision) Authoritative sources are prd.md and addendum.md in prds/prd-ShiftMind-2026-07-21; reconcile-scenario-data-viewer.md confirms there are no unresolved scope conflicts.
- (decision) Preserve the implemented React/Vite desktop-web foundation using shadcn/ui, Tailwind, Radix, React Router, and TanStack Query; DESIGN.md specifies only ShiftMind brand and component deltas.
- (decision) The scenario workspace has four peer views: Chat, Scenario Data, Runs, and Results. The selected scenario and immutable fixture version remain visible across views.
- (decision) Scenario Data is strictly read-only: no upload, create, edit, delete, import, inline-edit, selectable editable cells, or mutation-looking controls. Copying identifiers and opening evidence are allowed.
- (decision) Scenario Data groups normalized data into Overview, Work areas and tasks, Workers, Demand, Baseline assignments, Locks, and Constraints and objectives; each group exposes stable identifiers and fixture version context.
- (decision) Large tables use a dense but readable data-grid contract: sticky column headers, a sticky primary identifier column where useful, explicit sorting and filtering, bounded row virtualization or pagination, column visibility controls, and horizontal scroll contained inside the table region.
- (decision) Agent numerical and schedule-specific claims render structured Evidence links beside the claim. A link targets the exact scenario version, evidence group, record identifier, and optional field/time range; activating it opens Scenario Data at the matching row/cell without losing the conversation position.
- (decision) Evidence deep links are version-bound. Missing evidence, unauthorized evidence, and version mismatch are distinct states; the UI never silently falls back to a different version or row.
- (decision) Chat separates planner messages, grounded agent responses, clarification requests, reversible draft cards, run-progress cards, comparison summaries, approval requests, and terminal outcomes; the composer cannot visually imply that sending text itself approves or promotes a schedule.
- (decision) Loading, empty, error, unavailable, stale, and permission-denied states are defined per surface. Existing saved Scenario Data and results stay reachable when the model is unavailable.
- (decision) Accessibility floor is WCAG 2.2 AA, keyboard-complete desktop interaction, meaningful status text rather than color alone, announced durable progress, table semantics, focus restoration after evidence navigation, and reduced-motion support.
- (assumption) The existing indigo accent and neutral shadcn palette are retained because no brand refresh was requested; dark mode remains inherited but is not an MVP product requirement.
- (assumption) Desktop and laptop are primary; tablet is supported through stacked panels and contained table scrolling, while phone use is read-only triage rather than the full planning workflow.
- (assumption) Scenario scale is large enough to require virtualization or pagination, but exact row-count thresholds remain implementation-tunable as long as focus, sorting, filtering, and deep-link targeting stay deterministic.
- (assumption) Maya remains the named fictional planner from the PRD; no new persona, brand promise, regulated claim, offline-write behavior, or notification system is introduced.
- (event) Updated PRD inputs reconciled: read-only Scenario Data, evidence navigation, all principal loading/error/empty/stale states, large-table behavior, agent chat authority boundaries, and future claim-to-evidence links are present; no qualitative input was dropped.
- (decision) Headless fast path keeps Fixture catalogue, Chat, Scenario Data, Runs, and Results as spine-only surfaces; no mockup or wireframe is promoted.
