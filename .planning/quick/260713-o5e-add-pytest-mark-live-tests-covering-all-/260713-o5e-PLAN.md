  <action>
    Append a new gated live test near the existing live parity test (the
    "Live parity test" section at the bottom of the file). Mirror the existing gate
    exactly: decorate with `@pytest.mark.live` then
    `@pytest.mark.skipif(not _HAS_KEY, reason="GEMINI_API_KEY not set — live test requires a real key")`.
    Name it `test_gemini_generate_insights_passes_grounding_guard`.

    Inside, build the provider with `create_provider("gemini", settings=default_settings())`
    (default_settings picks up LLM_MODEL / GEMINI_API_KEY from env, same as the existing
    live test) and import the REAL guard with `from services.insight_service import _grounding_guard`
    — import the actual function, never re-implement it, so a future regression in the
    guard's rounding ladder is caught.

    Construct a realistic metrics dict that reproduces the run-418577f3 shape from the
    resolved bug so the same whole-number roundings that broke the guard ("98", "212",
    "11550"/"11,550", "61") are exercised against real Gemini prose:
      total_cost = 11549.71, total_unmet_hours = 212.127, scheduled_shifts = 42,
      scheduled_members = 18,
      coverage_by_function = {
        "Putaways": {"required_h": 270.0, "served_h": 265.0, "pct": 0.9814814814814815},
        "Pick": {"required_h": 300.0, "served_h": 300.0, "pct": 1.0},
      },
      coverage_by_day = {"0": 0.6122, "1": 0.95}.
    Wrap it as the summary generate_insights expects (mirrors insight_service.get_or_generate):
    summary = {"metrics": metrics, "warnings": [], "overrides": []}.

    Call report = provider.generate_insights(summary). Assert the report is a non-empty
    string (report.strip() is truthy) so an empty/safety-blocked "" response cannot vacuously
    pass the guard and hide the regression. Then call `_grounding_guard(report, metrics)` and
    assert it does not raise (a bare call inside the test body — if it raises
    InsightGenerationError the test fails, which is exactly the insight-api-502-ungrounded
    regression signal). Add an inline comment noting the 98.148% Putaways coverage is the
    whole-number-rounding case behind the bug, and that we deliberately do not hard-assert
    a specific token like the whole-number percent because real Gemini phrasing varies
    (98%, 98.1%, 98.15%) — the guard passing on genuine model output is the assertion.

    Keep imports local to the test (from llm.base import create_provider; from settings
    import default_settings; from services.insight_service import _grounding_guard),
    matching the existing file's per-test import idiom. Do not touch pyproject.toml, conftest,
    or any source file.
