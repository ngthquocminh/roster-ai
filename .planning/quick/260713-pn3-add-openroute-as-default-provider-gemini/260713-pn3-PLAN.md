<objective>
Add "openrouter" as a third, fully-registered, selectable `LLMProvider` alongside "stub" and "gemini", so a developer can set `LLM_PROVIDER=openrouter` locally and run manual/live testing against OpenRouter's higher free-tier throughput instead of Gemini's 50-req/day quota.

The new provider mirrors `GeminiLLMProvider`'s shape and contract exactly: tool/function-calling drives `parse_constraints`, a plain chat completion drives `generate_insights`, vendor errors map to the neutral `LLMProviderError`, and client construction is deferred to first use so the factory stays keyless (D-04). OpenRouter is OpenAI-API-compatible, so integration is the `openai` Python SDK pointed at `https://openrouter.ai/api/v1`.

Purpose: Unblock day-to-day local iteration without burning the Gemini free-tier quota, while keeping the stub the keyless CI default and every provider-neutral seam (D-02/D-06/D-07) intact.
Output: `backend/llm/openrouter.py`, a registered factory branch, extended settings, the `openai` dependency, a mirrored test module, and a SUMMARY.md documenting the local env vars a developer must set.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider -> OpenRouter API | Outbound network call carrying the API key and user NL text over HTTPS |
| env -> Settings -> provider | `OPENROUTER_API_KEY` (secret) crosses from environment into the provider |
| OpenRouter response -> LLMProvider seam | Untrusted vendor payload (tool-call JSON string) must not cross the seam as-is |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-pn3-01 | Information Disclosure | `Settings.openrouter_api_key`, provider | high | mitigate | `field(repr=False)` on the key (mirror T-04-01); key only flows into `OpenAI(api_key=...)`; never interpolated into logs, strings, or exceptions |
| T-pn3-02 | Tampering (supply chain) | `openai` pip dependency | medium | accept | `openai` is the official OpenAI SDK (pypi.org/project/openai, top-tier download volume, first-party); pin `>=1.40` minimum. No new obscure package introduced |
| T-pn3-03 | Information Disclosure | vendor exception crossing seam | medium | mitigate | Catch `openai.OpenAIError` and re-raise `LLMProviderError` with a STATIC message — vendor exception (which may carry request/headers) never propagates; callers already map LLMProviderError -> 503 |
| T-pn3-04 | Tampering | NL-derived constraints reaching the solver | medium | accept | No new exposure: provider only emits `OverrideCall`s through the same `to_override_call` seam; overrides remain soft round-2 penalties in the engine (existing architecture), never able to make a solve infeasible |
| T-pn3-05 | Spoofing/Repudiation | `OPENROUTER_MODEL` env override | low | accept | Model slug is non-secret config; a bad slug fails the API call which maps to LLMProviderError -> 503; documented fallback default in code |
</threat_model>
