<objective>
Add optional `.env` support for the backend LLM provider config so a developer can
set `LLM_PROVIDER` / `LLM_MODEL` / `GEMINI_API_KEY` in a local file instead of
exporting OS env vars. Ships a committed `backend/.env.example` and a gitignored
`backend/.env`.

Purpose: Lower friction for local runs (API server, `run.py` CLI, and pytest all
pick up the same file) without touching solver code or leaking secrets.
Output: `python-dotenv` dependency, a one-time module-level `load_dotenv` in
`backend/settings.py`, `backend/.env.example` (committed), `backend/.env`
(ignored), and `.gitignore` rules.
</objective>

  <name>Task 2: Load .env once in settings.py before default_settings reads env</name>
  <read_first>backend/settings.py</read_first>
  <files>backend/settings.py</files>
  <action>
    In backend/settings.py, import load_dotenv from dotenv (add `from dotenv import
    load_dotenv` to the imports) and call it exactly once at module scope, placed
    AFTER the `_BACKEND_DIR = Path(__file__).resolve().parent` line and BEFORE the
    Settings dataclass / default_settings definition. The call must be:
    `load_dotenv(_BACKEND_DIR / ".env", override=False)`.

    Rationale to preserve: resolving the path relative to _BACKEND_DIR makes it
    CWD-independent (works for the API server, run.py CLI, and pytest regardless of
    where the process starts). override=False guarantees a real OS environment
    variable still wins over the file, and an empty `GEMINI_API_KEY=` in the file
    does NOT clobber an already-set OS key. Because default_settings() reads
    os.environ fresh per call, loading the file into os.environ at import time is
    sufficient — no other module needs to change.

    Update the module docstring's "dependency-free" note: it now has one lightweight
    config-layer dependency (python-dotenv). Do not add any solver/web/domain
    imports — this stays in the config layer only.
  </action>
  <verify>
    <automated>cd backend && GEMINI_API_KEY= uv run python -c "import settings; s=settings.default_settings(); print(s.llm_provider)"</automated>
  </verify>
  <done>Importing settings triggers load_dotenv once; default_settings() still returns provider "stub" by default and a real OS env var overrides any .env value.</done>
</task>
