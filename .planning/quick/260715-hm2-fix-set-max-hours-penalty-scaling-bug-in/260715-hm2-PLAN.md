<objective>
Fix the `set_max_hours` penalty scaling bug in the CP-SAT builder. The `over` overflow
IntVar is scaled by `C.VOL_SCALE` (hundredths-of-an-hour), but its penalty term in
`round2_cost` multiplies by `C.MAX_HOURS_PENALTY` without dividing the `VOL_SCALE` factor
back out. Because both `VOL_SCALE` and `COST_SCALE` are `100`, this inflates the effective
penalty ~100x above the documented $1,000/hour-over-cap rate.

Purpose: Restore the intended, calibrated penalty magnitude so `set_max_hours` overrides
cost what `config/constants.py` documents, not 100x that.
Output: One code change in `builder.py`, one stale test docstring corrected in
`test_engine_overrides.py`.
</objective>

    currently reads `+ C.MAX_HOURS_PENALTY * sum(maxh_terms)`. Change the coefficient to
    `(C.MAX_HOURS_PENALTY // C.VOL_SCALE)` so the term becomes
    `+ (C.MAX_HOURS_PENALTY // C.VOL_SCALE) * sum(maxh_terms)`. Integer floor division is
    exact here: `100_000 // 100 == 1000`, with no rounding loss since both constants are
    clean multiples of 100.

    unscaled headcount/boolean vars and already land in COST_SCALE/cents unit space; `over`

    must be stripped back out before summing into cents-space round2_cost).

    LOCK_SHIFT_PENALTY, EXCLUDE_WORKER_PENALTY) — they are already correct. Do NOT touch the
