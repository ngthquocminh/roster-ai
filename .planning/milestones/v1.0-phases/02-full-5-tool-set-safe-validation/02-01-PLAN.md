<objective>
Rework the Phase-1 single-call constraint endpoint into the Phase-2 partial-apply
contract and parse-UX backbone that all five tools ride on. One text yields 0, 1,
or many tool calls; valid ones are applied, bad references/args are rejected with
plain-English guidance, ambiguous/incomplete fragments ask for clarification — all
in one 200 body, all driven by the stub with zero network calls.

## Phase Goal (user story)

**As a** scheduler, **I want to** express scheduling constraints in plain English
and get clear feedback on what was understood, rejected, or needs clarifying, **so
that** I can tune the roster safely without touching solver code or JSON.

Purpose: Establishes the response contract, reference-resolution, and parse-UX
signals (NLC-03/04/05, VAL-02/03) that Plan 02-02 extends to the four new tools.
Output: New structured ConstraintParseResponse end-to-end for the already-wired
`set_min_workers_per_task` tool, plus reusable `_resolve_member` and clarification
plumbing.
</objective>
