<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process → Gemini API | Outbound network call to generativelanguage.googleapis.com carrying the bearer API key |
| NL text → model → tool args | Untrusted user constraint text influences the model's function-call arguments |
| npm/pip install | `uv add google-genai` pulls a third-party package into the runtime |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-SC | Tampering | `uv add google-genai` (SUS legitimacy verdict) | high | mitigate | Blocking human-verify checkpoint (Task 1) confirms package identity on pypi.org + github.com/googleapis/python-genai before install; verdict recorded in RESEARCH Package Legitimacy Audit; never auto-approved. |
| T-04-01 | Information Disclosure | Gemini API key at client construction + error paths | high | mitigate | Key flows only as `GeminiLLMProvider.__init__(api_key=...)` into `genai.Client`; never logged, persisted, returned, or interpolated into any string/exception in gemini.py. insight_service already wraps provider errors as `InsightGenerationError(f"Provider failed: {exc}")` — this plan must not add the key to any exception the SDK could surface; flag SDK-exception-contains-key as a code-review check. |
| T-04-02 | Tampering | Prompt injection via NL text → out-of-schema/out-of-bounds tool args | medium | mitigate | Unchanged, provider-agnostic `constraint_service` VAL-01/VAL-02 (bounds + real-id resolution) scrutinizes every OverrideCall regardless of producer; Gemini output is just another `list[OverrideCall]`. AUTO mode + declaration-only tools (no auto-execute) prevent the SDK from invoking anything. |
| T-04-03 | Denial of Service | Denial-of-wallet: repeated live Gemini calls in CI exhausting the free tier | medium | mitigate | `live` marker excluded by default (`addopts = -m "not live"`) + skipif on missing key ⇒ default CI makes zero Gemini calls; only an explicit `pytest -m live` with a key set incurs quota. |
| T-04-05 | Denial of Service | An LLM/network failure invalidating a computed schedule (resilience rule) | high | mitigate | Insight generation is a separate post-run step; provider exceptions are wrapped into `InsightGenerationError` (router → 502) and never mutate run status (INS-02, unchanged). Parse failures surface as errors before the solve and never corrupt a stored schedule. |
| T-04-04 | Tampering | Fabricated numeric content in Gemini-authored insight text | low | accept | Existing Phase-3 `_grounding_guard` (D-06, provider-agnostic, unchanged) rejects any numeric token not traceable to the run's metrics; the insight prompt additionally instructs the model to cite only supplied figures. |
</threat_model>
