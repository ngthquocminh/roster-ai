<objective>
Prove the engine half of the seam: an `OverrideCall` for `set_min_workers_per_task`
makes CP-SAT place at least N workers on the named task at every demanded hour, as a
SOFT round-2 penalty that can never make the model infeasible — while a scenario with
no overrides solves byte-identically to today.

Purpose: This is the riskiest, most self-contained slice (solver internals). Landing it
first establishes the shared `OverrideCall` domain interface every later plan consumes,
and proves the safety guarantee (soft-only, round-2-only) in isolation via the real
CP-SAT engine before any LLM/API code exists.

Output: `domain/overrides.py` (the engine<->LLM decoupling seam), `SolverConfig.overrides`,
the `MIN_WORKERS_PENALTY` constant, the builder shortfall penalty, and an engine-level
test that observes the schedule honoring the override plus a no-regression baseline.

User story (phase goal, derived from CLAUDE.md core value + ROADMAP Phase 1 goal):
**As a** workforce scheduler, **I want to** state a staffing floor in plain English and
re-solve, **so that** the schedule honors it without my editing solver code or JSON.
This plan delivers the solver behavior that makes "honors it" true.
</objective>
