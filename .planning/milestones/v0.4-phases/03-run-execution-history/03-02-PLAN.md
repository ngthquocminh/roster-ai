<objective>
Build the two React Query hooks that make a run observable: useRuns (a self-terminating polling list query) and useTriggerRun (a mutation that triggers a solve and forces the new run to appear immediately). Purpose: Encapsulate the load-bearing polling lifecycle — poll while any run is non-terminal, stop the instant all are terminal — in one tested hook, and guarantee the trigger→appear link via a byte-identical invalidation key.
Output: frontend/src/hooks/useRuns.ts (+ test) and frontend/src/hooks/useTriggerRun.ts (+ test).
</objective>

| polling loop → browser resources | the refetchInterval schedules repeated background fetches; an unbounded interval is a self-inflicted client-side resource drain (DoS-on-self). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-03 | Denial of service | useRuns refetchInterval | medium | mitigate | The interval predicate returns false the instant hasActiveRun is false, so polling self-terminates when all runs are terminal; React Query clears the interval on unmount. No setInterval is hand-rolled, so no orphaned timer can outlive the component. Unit-tested against RUNNING / all-terminal / empty snapshots. |
| T-3-04 | Tampering | ["runs", scenarioId] key drift | low | mitigate | useTriggerRun's invalidation key and useRuns's query key are asserted byte-identical in tests, preventing a silent "run triggered but never appears" state. |
