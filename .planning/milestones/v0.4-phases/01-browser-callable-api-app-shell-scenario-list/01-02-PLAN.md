<planner_note>
**Why this is a standalone plan, and why it survives `human_verify_mode: end-of-phase`.**

`.planning/config.json` sets `workflow.human_verify_mode: end-of-phase`, which normally converts
`checkpoint:human-verify` tasks into `<verify><human-check>` blocks collected at phase end. Every
*other* human verification in this phase has been converted that way (see 01-01 Task 2, 01-03 Task 3,
01-05, 01-06, 01-07).

This one is deliberately NOT converted, for one reason: it is a **security gate, not a UX
verification**. `human_verify_mode` governs *when a human confirms Claude's work looks right* — a
cadence knob. A supply-chain gate governs *whether an install is permitted to run at all*, and
deferring it to end-of-phase would mean the packages are already installed and executing postinstall
scripts by the time the human is asked. That inverts the gate into a formality. The legitimacy
protocol states these checkpoints are never auto-approvable; a gate that fires after the irreversible
action is auto-approval with extra steps.

It is a standalone plan because a checkpoint must not share a plan with the implementation it gates.
</planner_note>
