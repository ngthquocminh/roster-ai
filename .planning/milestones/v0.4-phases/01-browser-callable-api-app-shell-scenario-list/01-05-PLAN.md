    Create `ErrorBanner.tsx` as a **persistent inline banner**, not a toast. UI-SPEC is explicit about
    this: a toast auto-dismisses, and a dismissed message about a backend that is still down is a
    silent failure wearing a notification's clothes. Build it on the shadcn `alert` primitive.

    Its copy is a **fixed literal** from UI-SPEC's Copywriting Contract — reproduce it exactly,
    including the parenthesised `uv run uvicorn api.main:app --reload` command and the `backend/`
    reference. Render the command as a text node so it wraps rather than truncating; truncating a
    remediation command destroys the reason the banner exists (UI-SPEC E6/long-text). The banner wraps
    to multiple lines within the fixed-width content column and is never clipped or internally
    scrolled (E6/overflow).

    **The banner must accept an error and ignore its contents.** This is the counter-intuitive part and
    it is deliberate:
    - It must not render the caught error's `.message`, `.stack`, or the backend's raw `detail` for
      unexpected failures (T-1-02, ASVS V7). Take the error as a prop only so callers have a uniform
      signature and so it can be logged to the console — never as render input.
    - It must not attempt to distinguish "CORS blocked" from "backend not running". `fetch` cannot tell
      them apart: browsers deliberately withhold CORS-failure specifics from JS so an attacker page
      cannot learn *why* a cross-origin request failed. Both surface as a generic `TypeError: Failed to
      fetch`. Any branch inspecting the error text for a CORS substring is unreliable across browsers
      and would be **fabricated confidence** — the fixed copy's non-diagnostic vagueness is the honest
      answer, not a gap to be closed. This is a locked prohibition on this plan.

    where the diagnostic detail lives (the console), which is the honest split — detail for whoever can
    use it, no wall of stack trace for whoever cannot.

    unmatched-route gap using copy UI-SPEC **already specifies**, rather than inventing new
    not-found copy that the design contract never approved.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caught error object → rendered UI | Errors originating in the backend or the network carry text (exception messages, stack traces, `detail` strings, file paths) that must not reach the user's screen. |
| URL bar → route table | Any path, including undeclared and malformed ones, is user-controlled input to the router. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-02 | Information Disclosure | `ErrorBanner.tsx`, `RootErrorBoundary.tsx` | medium | mitigate | Both render **fixed literal copy** from UI-SPEC's Copywriting Contract. The error object is accepted as a prop for console logging only and is never render input — no `.message`, no `.stack`, no raw backend `detail` reaches JSX for unexpected (5xx/network) failures. Gated by the `.stack` grep and by a test that injects a fake stack trace into `.message` and asserts its absence from the output. Known 4xx `detail` strings are handled separately and inline, per UI-SPEC (plan 01-07). |
| T-1-07 | Information Disclosure | route table / undeclared paths | low | mitigate | An unmatched URL routes to the root `errorElement` rendering UI-SPEC's fixed crash-backstop copy, rather than react-router's built-in default error page — which is developer-facing and can echo route internals. Gated by the `/nope` deep-link test. |

No package-manager installs occur in this plan (it consumes deps installed by 01-03, which is gated by
01-02's blocking legitimacy checkpoint), so no `T-1-SC` row applies here.
