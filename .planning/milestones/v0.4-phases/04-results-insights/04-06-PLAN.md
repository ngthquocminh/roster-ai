<objective>
Build the on-demand insight panel: a button-triggered report fetch with five honest states — idle, generating, ready (report), not-ready (branch on `ready`), and failed (distinct error + retry). This is the RES-04/RES-05 lynchpin: it must branch on the response body's `ready` field (never the status code) and its failure must never touch the rest of the results page.

Purpose: GET /runs/{id}/insights returns 200 {ready:false} when not COMPLETED (deliberately NOT 409) and 502 on generation failure — the two endpoints (/result vs /insights) must not be treated alike. And per this project's core resilience principle, an insight failure is a separate post-run step that never invalidates a computed schedule.
Output: InsightPanel.tsx (+ test).
</objective>
