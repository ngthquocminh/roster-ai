<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input → POST /constraints | Untrusted constraint text (1–2000 chars) crosses to the API |
| server response → JSX render | parsed_constraint / rejected error / clarification strings (server-influenced) rendered in the transcript |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-13 | Tampering / Information Disclosure | TranscriptEntry text render | medium | mitigate | React default JSX escaping for parsed_constraint/error/clarification strings; no dangerouslySetInnerHTML (T-1-03 convention). |
| T-02-14 | Spoofing | 503-vs-422 honesty (CONS-05) | high | mitigate | Branch strictly on response.status; the 503 path is structurally disjoint from the 200-body rejection render (ProviderDownBanner vs TranscriptEntry), so a provider outage can never be rendered as "your input was wrong". Unit-tested (variant + preservation). |
| T-02-15 | Denial of Service | oversized input round-trip | low | mitigate | Client-side length gate (submit disabled past 2000) prevents guaranteed-422 round trips; server Field(max_length=2000) remains the authoritative boundary (ASVS V5 L1). |
| T-02-16 | Repudiation/UX | lost user input | medium | mitigate | Input-preservation rule keeps typed text across every non-full-success outcome (CONS-04); unit-tested. |
| T-02-SC | Tampering | dependency installs | low | accept | No package installs — composes Textarea (plan 02-02), Button, Alert, lucide-react (all present). |

Block-on = high. T-02-14 is high but disposition=mitigate with a structurally-disjoint, unit-tested mitigation → not blocking.
</threat_model>
