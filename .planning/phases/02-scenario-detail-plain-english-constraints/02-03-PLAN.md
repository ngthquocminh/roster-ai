<objective>
Add the three TanStack Query hooks that drive the Editor: two reads (scenario detail, overrides — the overrides read being a dependent query) and one mutation (apply constraint, invalidating the overrides list). These wrap the plan-02-02 wrappers with the repo's established query-key + invalidation contract.

Purpose: Server state stays in TanStack Query (no raw fetch+useState); the apply-mutation → overrides-list invalidation is the mechanism by which newly applied overrides appear (criterion 2); the dependent query keeps the two Editor fetches independently observable (UI-SPEC E1/E2).
Output: `useScenario`, `useOverrides`, `useApplyConstraint` (+ tests).
</objective>
