    URL `docs/API.md` documents.

    counter-intuitive and silently breaks otherwise: the *page* origin is what CORS checks, not this
    URL. Browsing to `http://localhost:5173` (the Vite default, and the first entry in the backend's

    origin is on the allow-list. Browsing to `http://127.0.0.1:5173` does NOT work, because that page
    origin is absent from the backend's default allow-list even though it is the same machine. Note
    that the fix is to add it to the backend's `CORS_ORIGINS`, not to change this variable.

    Do not add `frontend/.env` to `.gitignore` — the root `.gitignore` already ignores `.env` and
    `.env.*` at any depth while un-ignoring `.env.example` (lines 28-31). Verify this rather than

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → developer machine | `npm create vite`, `npm install`, and `npx shadcn` fetch and execute third-party code with full developer privileges. |
| build-time env → shipped bundle | Anything in a `VITE_*` var is inlined into the public static bundle at build time and is world-readable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-SC | Tampering | npm/npx installs in Task 1 and Task 3 | high | mitigate | Gated by plan 01-02's blocking-human legitimacy checkpoint, which this plan `depends_on`. Task 1 must confirm 01-02-SUMMARY records approval before running any install. `[SLOP]`-verdict `msw` is excluded, enforced by a `package.json` assertion in both Task 1 and Task 3. |
| T-1-05 | Information Disclosure | `frontend/.env.example`, `VITE_*` vars | low | mitigate | Vite inlines every `VITE_*` var into the client bundle at build time, so any secret placed there ships to every visitor. Only `VITE_API_BASE_URL` — a public endpoint address, not a secret — is defined. The backend's real secrets (`GEMINI_API_KEY`, `OPENROUTER_API_KEY`) stay in `backend/.env`, on the far side of the process boundary, and must never be mirrored into `frontend/.env*`. `frontend/.env` is gitignored by the root rules (verified in Task 2), `.env.example` carries no secret values. |
</threat_model>
