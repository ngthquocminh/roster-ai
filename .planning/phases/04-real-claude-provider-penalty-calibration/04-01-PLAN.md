<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env → process | LLM provider/model/key read from the OS environment into the frozen Settings object |
| config → provider factory | `settings.llm_provider` string selects which backend `create_provider` instantiates |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Information Disclosure | `Settings.llm_api_key` (GEMINI_API_KEY read into process) | high | mitigate | Key is read only into `Settings.llm_api_key`; it is never logged, never persisted to SQLite/JSON, never returned in an API response, and never interpolated into an exception message in settings.py/deps.py/base.py. Enforced here by construction (no string uses the key); the network-side leak vector is handled in 04-02's threat model. |
| T-04-02 | Elevation of Privilege | `create_provider` unknown-name path | low | mitigate | Unknown provider names raise `ValueError` (fail closed); no dynamic import of an arbitrary attacker-supplied module name — only the fixed `"stub"`/(later) `"gemini"` branches. |
| T-04-03 | Tampering | env-driven provider selection defaulting keyless | medium | mitigate | Default `LLM_PROVIDER="stub"` means the no-config path performs zero network calls; enabling a real provider is an explicit operator action requiring a key to be present. |
</threat_model>
